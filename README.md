# Interview Trainer

Локальный тренажёр собеседований на позиции **LLM / NLP / DL / AI Engineer**.

Главная функция — интервьюер, который задаёт вопрос и **не отстаёт**, пока не станет
ясно, понимаешь ты решение или пересказываешь туториал. Весь инференс локальный
(Ollama), знание живёт в банке вопросов, а не в модели: она только сверяет текст
кандидата с эталоном.

Полное ТЗ — [`docs/spec.md`](docs/spec.md).

## Статус

**v0 — режим квиза — работает.** Вопрос из банка → открытый ответ → механическая
сверка с эталоном → таблица `covered / partial / missed`, противоречия эталону и
оценка. Ничего не сохраняется, уточняющих вопросов нет (`max_followups = 0`).

Следующий шаг — v1: мок-интервью с уточняющими и SQLite. См. «Фазы» в ТЗ.

## Банк

`banks/bank_full.json` — 500 вопросов: LLM (122), Классический ML (67),
Статистика (62), Computer Vision (53), Основы DL (50), MLOps (47), NLP (45),
Системный дизайн (30), HR-скрининг (24). У каждого — 5 `points` и связный `ref`.

Формат карточки:

```json
{"id": "kv", "track": "LLM", "topic": "Инференс",
 "q": "Зачем нужен KV-cache и что он ломает при батчинге?",
 "points": ["...", "...", "...", "...", "..."],
 "ref": "Связный эталонный ответ на 4-5 предложений."}
```

Загрузчик понимает и YAML-банки с длинными именами полей
(`question` / `key_points` / `reference`) — имена взаимозаменяемы в обоих форматах.

Три вещи едят один и тот же файл: `run.py` (тренажёр), `cards/interview_cards.html`
(карточки, банк вшит внутрь) и `tools/gen_bank.py` (генерация и дедуп).

### Доращивание банка

```bash
ollama pull bge-m3
pip install numpy

python tools/gen_bank.py --stats
python tools/gen_bank.py --track "Статистика" --topic "A/B-тесты" --n 15
python tools/gen_bank.py --track "Computer Vision" --auto
python tools/gen_bank.py --dedup-only
python tools/gen_bank.py --inject cards/interview_cards.html   # обновить карточки
```

Дедуп по косинусу эмбеддингов с порогом 0.86 — генератор регулярно выдаёт один
и тот же вопрос двумя формулировками. Отсев 50–70% сгенерированного — норма.

После `--dedup-only` или генерации прогони `--inject`, иначе карточки разъедутся
с банком (это ловит `tests/test_cards_sync.py`).

## Карточки

`cards/interview_cards.html` — самодостаточная страница для быстрого повторения:
вопрос → самооценка («знаю уверенно / примерно представляю / не знаю») → пункты
и эталон, прогресс в localStorage. Открывается двойным кликом, интернет не нужен
(кроме шрифтов). Это повторение, а не тренажёр: произносить ответ вслух
заставляет `run.py`.

**С телефона:** страница публикуется на GitHub Pages —
https://ganiesenov.github.io/interview-trainer/ . Деплой автоматический
(`.github/workflows/pages.yml`) при каждом пуше в `cards/`. Чтобы это заработало
в первый раз, один раз включи Pages: Settings → Pages → Source: **GitHub Actions**.
Прогресс хранится в localStorage браузера, то есть на телефоне он свой.

## Режимы

Квиз и мок-интервью — один движок, разница только в `max_followups`:

```
quiz  = вопрос → ответ → оценка                    (max_followups = 0)
mock  = вопрос → ответ → уточняющий ×N → вердикт   (max_followups = 3)
```

Ответ всегда открытый — никаких вариантов на выбор.

Рубрики: `project` (главная), `theory`, `sysdesign`, `coding`, `hr`, `pitch`.

## Запуск

```bash
ollama pull qwen2.5:32b-instruct-q4_K_M
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

python run.py                        # случайный вопрос из banks/bank_full.json
python run.py --track LLM            # только по направлению
python run.py --track LLM --topic RAG
python run.py --id kv                # конкретный вопрос
python run.py --stats                # покрытие банка по направлениям и темам
python run.py --list --track MLOps   # что вообще есть в банке
python run.py --model qwen3:32b      # другая модель
```

Ответ вводится в несколько строк, пустая строка — конец ответа.

Переменные окружения: `INTERVIEW_MODEL` (модель по умолчанию),
`OLLAMA_HOST` (по умолчанию `http://127.0.0.1:11434`).

`--track` и `--topic` нечувствительны к регистру и понимают префикс
(`--track llm`).

## Свой эталон (необязательно)

Если формулировка пунктов в банке не совпадает с тем, как ты отвечаешь, её можно
переписать под себя — тогда сверка пойдёт с твоей версией:

```bash
python run.py --mine kv        # записать или переписать свой эталон для вопроса
python run.py --list-mine      # по каким вопросам свой эталон уже есть
python run.py --bank-ref       # разово сверяться с банком, игнорируя свой
python run.py --ask-mine       # предлагать запись после каждого разбора
```

**По умолчанию тренажёр ничего не спрашивает** — механизм включается только явной
командой. Пункты пишутся по одному в строке, маркеры и нумерация срезаются.
Хранится в `data/my_answers.json` (git-ignored, это личное). Банковский эталон
никуда не девается — он по-прежнему печатается под разбором.

## План подготовки

[`docs/study-plan.md`](docs/study-plan.md) — ядро из 124 карточек под роль
LLM / NLP / AI Engineer, разложенное на 4 недели по дням, с первоисточником и
заданием «сделать руками» на каждый день. Остальные 376 карточек — справочник,
а не программа.

Состав дней правится в `tools/make_study_plan.py` (он проверяет, что все id есть
в банке, и подставляет актуальные тексты вопросов), после чего:

```bash
python tools/make_study_plan.py
```

Тесты (чистые части — парсинг JSON, сопоставление пунктов, подсчёт балла,
загрузка банка, синхронность карточек с банком): `pytest`.

## Как считается оценка

Модель расставляет только статусы по пунктам эталона. **Балл считается в Python**
(`covered` = 1, `partial` = 0.5, `missed` = 0 → доля, отображённая в 1–10) —
локальные модели проставляют баллы наугад, и её собственный `score` игнорируется.
Пункты модели сопоставляются с пунктами банка по похожести текста, поэтому
перестановка и пересказ своими словами не ломают разбор.
