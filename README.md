# Interview Trainer

Локальный тренажёр собеседований на позиции **LLM / NLP / DL / AI Engineer**.

Главная функция — интервьюер, который задаёт вопрос и **не отстаёт**, пока не станет
ясно, понимаешь ты решение или пересказываешь туториал. Весь инференс локальный
(Ollama), знание живёт в банке вопросов, а не в модели: она только сверяет текст
кандидата с эталоном.

Полное ТЗ — [`docs/spec.md`](docs/spec.md).

## Статус

**v1 — мок-интервью и память — работает.** Квиз (v0): вопрос → открытый ответ →
механическая сверка с эталоном → `covered / partial / missed` и оценка. Мок
(`--mock`): тот же движок, но пока остаются нераскрытые пункты, интервьюер задаёт
до трёх уточняющих, целясь именно в дыры (формулировки пунктов он не выдаёт);
вердикт показывает оценку первого ответа против финальной. Каждая сессия пишется
в SQLite: `--history` — журнал, `--weak` — слабые темы и вопросы, `--review` —
очередь повторения (плохие оценки возвращаются чаще: <5 — через день, 5–7 — через
три, ≥8 — через неделю).

Следующий шаг — v2 и веб-страница поверх движка. См. «Фазы» в ТЗ.

## Банк

`banks/bank_full.json` — 513 вопросов: LLM (132), Классический ML (68),
Статистика (62), Computer Vision (53), Основы DL (52), MLOps (47), NLP (45),
Системный дизайн (30), HR-скрининг (24). У каждого — 5 `points` и связный `ref`.

Формат карточки:

```json
{"id": "kv", "track": "LLM", "topic": "Инференс",
 "q": "Зачем нужен KV-cache и что он ломает при батчинге?",
 "points": ["...", "...", "...", "...", "..."],
 "ref": "Связный эталонный ответ на 4-5 предложений."}
```

Загрузчик понимает и YAML-банки с длинными именами полей
(`question` / `key_points` / `reference`) — имена взаимозаменяемы в обоих форматах.

Три вещи едят один и тот же файл: `run.py` (тренажёр), `cards/interview_cards.html`
(карточки, банк вшит внутрь) и `tools/gen_bank.py` (генерация и дедуп).

### Доращивание банка

```bash
ollama pull bge-m3
pip install numpy

python tools/gen_bank.py --stats
python tools/gen_bank.py --track "Статистика" --topic "A/B-тесты" --n 15
python tools/gen_bank.py --track "Computer Vision" --auto
python tools/gen_bank.py --dedup-only
python tools/build_cards.py                                    # обновить страницу карточек
```

Дедуп по косинусу эмбеддингов с порогом 0.86 — генератор регулярно выдаёт один
и тот же вопрос двумя формулировками. Отсев 50–70% сгенерированного — норма.

После `--dedup-only` или генерации прогони `tools/build_cards.py`, иначе страница
разъедется с банком (это ловит `tests/test_cards_sync.py`).

## Карточки и теория

`cards/interview_cards.html` — самодостаточная страница: и вопросы, и уроки теории
вшиты прямо в HTML, поэтому она работает с телефона без сервера.

Два режима:

- **Теория** — уроки, сгруппированные по восьми блокам (LLM: устройство → RAG →
  дообучение → DL → прод → статистика → смежные треки → глубина), с прогрессом
  «прочитано N/M» на каждом блоке. Схемы — не обложка, а по разделам внутри
  уроков: **62 SVG, у каждого урока 2–3** (`banks/figures.json`, генерируются `tools/gen_figures*.py`: кривые считаются из формул скриптом, а не
  рисуются на глаз — нормальные плотности α/β, bias-variance, LR range test,
  U-кривая lost-in-the-middle, скаттер Симпсона с настоящей регрессией, LIMA,
  затухание 0.25ⁿ, плюс схемы-конвейеры: трансформер, prefill/decode, RAG и его
  диагностика 2×2, LoRA, три энкодера, RLHF vs DPO, параллелизм, канареечная
  лестница, бюджет латентности, GroupKFold, BPE-мержи, слои обороны, хронометраж
  питча). В десяти уроках — код-сниппеты, которые надо уметь писать на доске
  (attention, LoRA-слой, InfoNCE, DPO-лосс, backprop руками, decode-цикл с
  KV-кэшем, RRF, размер выборки, обучение BPE, память тренировки). И в каждом —
  блок **«Смотреть и делать»**: отобранные видео (Karpathy, 3Blue1Brown,
  StatQuest), репозитории (nanoGPT, minbpe, vLLM, PEFT, TRL) и визуальные
  разборы (Illustrated Transformer, bbycroft.net/llm, kipply). Читаешь урок целиком, жмёшь
  «Пройти тест по уроку» — и колода сужается ровно до тех карточек, которые
  спрашивают прочитанное. Кнопка «назад» браузера/телефона работает как ожидаешь:
  закрывает урок, потом список, потом возвращает в колоду (History API).
- **Карточки** — вопрос → самооценка («знаю уверенно / примерно представляю /
  не знаю») → пункты и эталон; у 135 карточек (ядро плана + глубокий LLM-трек)
  под вердиктом есть кнопка **«Полный разбор»** — тот самый развёрнутый ответ из
  `docs/answers/` (30 секунд / 2 минуты / на бумаге / ловят на этом) прямо на
  странице, без похода на GitHub. Вкладка «Разбор» показывает, где самооценка
  расходится с делом.

Как карточки возвращаются — **кривая забывания** (ступени Лейтнера): назвал ≥80%
пунктов — карточка поднимается на ступень и вернётся позже (1 → 3 → 7 → 21 день),
провалил — падает на первую и вернётся завтра; в шапке видно, сколько карточек
«к повторению» сегодня, на карточке — её ступень. Провал в текущем сеансе не
зацикливает очередь: карточка вернётся в конце сеанса, а не немедленно. Каждые
10 карточек — сводка серии (доля названных пунктов, худшие направления) с кнопкой
«Ещё серия». Плюс поиск по вопросам и пунктам над колодой и клавиши: 1/2/3 —
самооценка, Enter — готово/дальше.

Ещё из удобств: **тёмная тема** (кнопка ◐ в шапке; по умолчанию следует системной,
выбор запоминается) и **экспорт/импорт прогресса** во вкладке «Разбор» — прогресс
живёт в localStorage браузера, поэтому перед чисткой браузера или при переезде на
другой телефон выгрузи JSON и импортируй на новом устройстве (слияние по свежести
записей, ничего не затирается).

Урок в `banks/lessons.json` устроен так:

```json
{"id": "l_llm_attention", "title": "Внимание и блок трансформера", "track": "LLM",
 "cards": ["attn", "mha", "..."], "minutes": 6,
 "tldr": ["3 главных вывода — показываются до текста"],
 "body": "лёгкий markdown: ## , - , **жирный**, `код`, > врезка",
 "sources": ["первоисточники — показываются после текста"]}
```

`minutes` считается автоматически из объёма, `tldr` и `sources` обязательны — без них
`build_cards.py` падает.
После правки банка или уроков:

```bash
python tools/build_cards.py    # вшивает CARDS, LESSONS и DEEP (разборы) в страницу
```

Скрипт падает, если урок ссылается на несуществующую карточку; расхождение страницы
с источниками ловит `tests/test_cards_sync.py`.

**25 уроков покрывают 193 карточки из 513**: 18 закрывают всё ядро плана — по одному
уроку на день из `docs/study-plan.md` — 5 добирают смежные треки, и ещё 2 углубляют
LLM-трек до уровня интервью в топ-лаборатории:

| Блок | Уроков | Темы |
|---|---:|---|
| LLM: устройство и инференс | 4 | внимание и блок трансформера, prefill/decode/батчинг, память и квантизация, длинный контекст |
| RAG и оценка | 4 | поиск как основа, RAG в проде, эмбеддинги, оценка генерации |
| Дообучение и DL | 5 | PEFT, данные для дообучения, алайнмент, фундамент DL, практика обучения |
| Прод и собеседование | 5 | наблюдаемость, выкатка, статистика для A/B, системный дизайн, HR-секция |
| Смежные треки | 5 | классический ML (фундамент; утечки и валидация), CV-минимум, NLP-классика, статистические ловушки |
| LLM: глубина | 2 | обучение в масштабе (scaling laws, ZeRO/FSDP, MoE, continued pretraining), безопасность (инъекции, red teaming, Constitutional AI) |

Структура урока: **Главное** (три вывода) → текст с подзаголовками и формулами →
врезка «что должно остаться в голове» → **Откуда это** (первоисточники кликабельными
ссылками) → кнопка теста. Время чтения — 4–6 минут на урок.

### Про достоверность

Уроки написаны языковой моделью. Числовые утверждения проверены расчётом
(размер KV-кэша, 16 байт на параметр для Adam, доля FFN в параметрах, сумма t² = n³/3,
вероятность ложного срабатывания при 20 метриках, надёжность агента на 20 шагов);
спорные места сверены с первоисточниками и исправлены. У каждого урока есть список
работ с прямыми ссылками, по которым можно проверить формулировку —
**сверяйся с ними, а не с тренажёром**.

**С телефона:** страница публикуется на GitHub Pages —
https://ganiesenov.github.io/interview-trainer/ . Деплой автоматический
(`.github/workflows/pages.yml`) при каждом пуше в `cards/`. Чтобы это заработало
в первый раз, один раз включи Pages: Settings → Pages → Source: **GitHub Actions**.
Прогресс хранится в localStorage браузера, то есть на телефоне он свой.

## Режимы

Квиз и мок-интервью — один движок, разница только в `max_followups`:

```
quiz  = вопрос → ответ → оценка                     (по умолчанию)
mock  = вопрос → ответ → уточняющий ×3 → вердикт    (--mock)
```

Уточняющие целятся в нераскрытые пункты, не подсказывая их; пустой ответ на
уточняющий — «пасую», бюджет тратится, оценка не портится задним числом.
Ответ всегда открытый — никаких вариантов на выбор.

Рубрики: `project` (главная), `theory`, `sysdesign`, `coding`, `hr`, `pitch`.

## Запуск

```bash
ollama pull qwen2.5:32b-instruct-q4_K_M
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

python run.py                        # случайный вопрос из banks/bank_full.json
python run.py --track LLM            # только по направлению
python run.py --track LLM --topic RAG
python run.py --id kv                # конкретный вопрос
python run.py --stats                # покрытие банка по направлениям и темам
python run.py --list --track MLOps   # что вообще есть в банке
python run.py --model qwen3:32b      # другая модель

python run.py --mock                 # мок-интервью: до 3 уточняющих по дырам
python run.py --mock --track LLM     # мок только по направлению
python run.py --history              # журнал последних сессий
python run.py --weak                 # слабые темы и вопросы на повторение
python run.py --review               # прогнать очередь повторения
python run.py --no-save              # не писать сессию в журнал
```

Ответ вводится в несколько строк, пустая строка — конец ответа.

Переменные окружения: `INTERVIEW_MODEL` (модель по умолчанию),
`OLLAMA_HOST` (по умолчанию `http://127.0.0.1:11434`).

`--track` и `--topic` нечувствительны к регистру и понимают префикс
(`--track llm`).

## Свой эталон (необязательно)

Если формулировка пунктов в банке не совпадает с тем, как ты отвечаешь, её можно
переписать под себя — тогда сверка пойдёт с твоей версией:

```bash
python run.py --mine kv        # записать или переписать свой эталон для вопроса
python run.py --list-mine      # по каким вопросам свой эталон уже есть
python run.py --bank-ref       # разово сверяться с банком, игнорируя свой
python run.py --ask-mine       # предлагать запись после каждого разбора
```

**По умолчанию тренажёр ничего не спрашивает** — механизм включается только явной
командой. Пункты пишутся по одному в строке, маркеры и нумерация срезаются.
Хранится в `data/my_answers.json` (git-ignored, это личное). Банковский эталон
никуда не девается — он по-прежнему печатается под разбором.

## Разборы

[`docs/answers/`](docs/answers/) — развёрнутые ответы на карточки ядра, по файлу на
неделю плана. Для каждого вопроса: **30 секунд** (что говоришь первым), **2 минуты**
(как разворачиваешь), **на бумаге** (что надо уметь вывести) и **ловят на этом** —
уточняющие вопросы, которые последуют, с ответами. Это то, чего нет в `points` и `ref`
банка: последовательность изложения и вторая линия обороны. Эти же разборы вшиты
в страницу карточек — кнопка «Полный разбор» под вердиктом самооценки.

Готовы все четыре недели: неделя 1 (28 карточек — внимание, инференс, память и
стоимость, длинный контекст), неделя 2 (25 — поиск и RAG в проде, эмбеддинги, оценка
генерации), неделя 3 (33 — PEFT, данные для дообучения, алайнмент и рассуждения,
фундамент DL, практика обучения) и неделя 4 (38 — наблюдаемость и выкатка в проде,
статистика A/B, системный дизайн LLM-сервисов, HR-секция и питч проекта).
Итого 124 разбора — весь дневной план. Плюс [`deep-llm.md`](docs/answers/deep-llm.md) — 11
разборов углублённого LLM-трека (scaling laws, параллелизм, bf16, MoE, continued
pretraining, инъекции, red teaming, Constitutional AI).

Тесты (чистые части — парсинг JSON, сопоставление пунктов, подсчёт балла,
загрузка банка, синхронность карточек с банком): `pytest`.

## Как считается оценка

Модель расставляет только статусы по пунктам эталона. **Балл считается в Python**
(`covered` = 1, `partial` = 0.5, `missed` = 0 → доля, отображённая в 1–10) —
локальные модели проставляют баллы наугад, и её собственный `score` игнорируется.
Пункты модели сопоставляются с пунктами банка по похожести текста, поэтому
перестановка и пересказ своими словами не ломают разбор.
